# LINE現場報告 → Googleスプレッドシート記録(試作)

専用のテストグループに招待した LINE公式アカウント が受け取ったメッセージのうち、**先頭が「【対応】」のテキストだけ**を、Googleスプレッドシートに1行ずつ記録します。

| 受信日時(日本時間) | 対応内容 | ステータス | イベントID |
|---|---|---|---|
| 2026-11-24 10:20:46 | 明日までに雨樋の見積もりを確認 | 未対応 | 01H… |

- **受信日時**: LINEのイベント時刻を、日本時間にしたものです。
- **対応内容**: 本文から目印「【対応】」と前後の空白を除いたものです。
- **イベントID**: LINEの `webhookEventId` です。

あとで、Dot がこのシートを読む想定です。Dot への接続や通知は、この試作の範囲外です。

## 記録しないもの
- 許可したテストグループ以外の投稿、個別のトーク
- 目印のない投稿、目印が途中にある投稿、目印だけで中身のない投稿
- 画像・動画・音声・ファイル・スタンプ・位置情報
- LINEへの自動返信や、AIでの分類は行いません。

## 安全のための作り
- **署名の検証**: 受け取った本文そのものと `X-Line-Signature` で、署名を検証します。失敗したら401を返し、シートにも記録にも一切書きません。
- **許可したグループだけ**: 設定したグループIDだけを処理します。設定が空なら、何も記録しません。
- **二重記録の防止**: イベントIDごとにファイルロックをかけます。LINEの再送が同時に届いても、1行だけ記録します。
- **失敗したら完了扱いにしない**: 書き込みに失敗したら500を返します。LINEの「Webhookの再送」で、もう一度書き込みます。書けたのに応答が来なかった場合は、再送のときにシートのイベントID列を確認してから、書くかどうかを決めます。
- **数式にしない**: シートへは `valueInputOption=RAW` で送ります。本文が「=」で始まっても、数式にはならず文字列として入ります。
- **最小限の権限**: Google には、スプレッドシートの権限(`spreadsheets` スコープ)だけを要求します。シートはサービスアカウントにだけ共有し、公開しません。
- **ログ**: 処理の結果(イベントID・記録した/しなかった理由)だけを書きます。投稿本文・シークレット・トークン・グループID・ユーザーIDは書きません。グループIDを確認するモードを有効にしたときだけ、参加したグループのIDを書きます。
- **保存しないもの**: シークレットや鍵はコードにもGitにも入れず、公開フォルダの外の設定ファイルに置きます。処理状況として保存するのは、イベントIDのハッシュと状態だけで、本文は保存しません。

## 構成
```
line-report-logger/
  public/index.php          受け口(公開フォルダに置くのはこれだけ)
  src/                      処理本体(公開フォルダの外に置く)
    Signature.php           署名の検証
    EventFilter.php         記録対象かの判定と、1行の組み立て
    EventStore.php          二重記録の防止(イベントIDごとのロックと状態)
    GoogleSheetsClient.php  Sheets API への書き込み(サービスアカウント認証)
    WebhookHandler.php      全体の流れ
    Logger.php              安全なログ
    bootstrap.php           設定の読み込みと組み立て
  config/config.sample.php  設定の見本(本物の config.php はGitに入れない)
  tests/                    試験(架空データのみ)
```
PHP 7.4 以上で動きます(外部ライブラリ不要。curl・openssl・json・mbstring・ctype を使います)。

> **なぜ Google Apps Script を使わないのか**: Apps Script の受け口(doPost)では、リクエストのヘッダーを読めません。そのため、LINEの署名(`X-Line-Signature`)を検証できないからです。

## ローカルでの試験
本物の LINE・Google・認証情報は使いません。偽物の Google(`tests/mock_google.php`)を使います。
```bash
cd line-report-logger
php tests/unit.php   # 単体試験(偽物の書き込み口)
php tests/e2e.php    # 通し試験(ローカルのHTTPサーバー + 偽物のGoogle。同時受信も試す)
```

### 手元で試しに送る
```bash
php tests/demo.php
```
受け口(http://127.0.0.1:8080/)と偽物の Google が起動します。表示されるコマンドを別の端末で実行すると、署名つきの架空の投稿を送れます。止めるときは Ctrl+C を押します。試験用のファイルは自動で消えます。

## 次の段階: 本物につなぐときの設定手順
**テストは架空のデータだけで行ってください。** 目印で絞り込んでいても、受信の時点では、グループのほかの投稿もこの仕組みに届きます。**既存の業務グループには、絶対に招待しないでください。**

### 1. テスト用シート(Google)
1. Google Cloud で、テスト用のプロジェクトを作ります(既存のものでも構いません)。
2. 「APIとサービス」で、**Google Sheets API** を有効にします。
3. 「サービスアカウント」を作ります。プロジェクトへの役割(ロール)は**付けません**。
4. そのサービスアカウントの**鍵(JSON)**を作って、ダウンロードします。
   - この鍵は、パスワードと同じ扱いです。メールやチャットに貼らず、Gitにも入れないでください。
   - 組織の設定で鍵を作れない場合は、管理者に相談してください。
5. テスト用のスプレッドシートを新しく作ります。
   - シート名は `対応記録` にします(変える場合は、設定ファイルも合わせます)。
   - 1行目に見出しを入れます: `受信日時` `対応内容` `ステータス` `イベントID`
6. シートの「共有」で、**サービスアカウントのメールアドレス(…@….iam.gserviceaccount.com)だけを「編集者」で追加**します。
   - 「リンクを知っている全員」は**オフ**のままにしてください。
7. シートのURLの `/d/` と `/edit` の間が、**スプレッドシートID** です。

### 2. Webhookの公開先(エックスサーバーの例)
1. WordPressとは別の、**専用のサブドメイン**を作ります(例: `line-hook.kamisei.co.jp`)。SSL(https)を有効にします。
   - **アクセス制限(ベーシック認証)はかけないでください。** かけると、LINEから届かなくなります。署名の検証で守ります。
2. ホームディレクトリの、**公開フォルダの外**に、次のように置きます。
   ```
   /home/USER/line-report-logger/src/        ← src/ をまるごと
   /home/USER/line-report-logger/config/config.php   ← config.sample.php をコピーして値を入れる(権限600)
   /home/USER/line-report-logger/secret/service-account.json  ← 鍵(権限600)
   /home/USER/line-report-logger/data/       ← 空のフォルダ(権限700)
   ```
3. サブドメインの公開フォルダに、`public/index.php` だけを置きます。
   - ファイルの上のほうにある2行(`$src` と `$config`)を、上の実際の場所に書き換えます。
4. `config.php` に、次の値を入れます。
   - `channel_secret`(LINEのチャネルシークレット)
   - `service_account_key_file`、`spreadsheet_id`、`sheet_name`、`data_dir`、`log_file`
   - `allowed_group_ids` は、次の手順でグループIDが分かってから入れます。
5. ブラウザで `https://line-hook.kamisei.co.jp/` を開いて、**405** が出れば置き場所は正しいです(POST以外は受け付けないため)。
6. エックスサーバーのWAF(セキュリティ機能)がLINEからのリクエストを止めていないかは、LINE側の「検証」ボタンで確かめます。403になる場合は、WAFの設定を確認してください。

### 3. LINE公式アカウント
1. テスト用の **LINE公式アカウント**を作ります(無料プランで構いません。受信には費用がかかりません)。
2. LINE Official Account Manager の設定で、次のようにします。
   - **Messaging API を有効化**する(LINE Developers のプロバイダーを選びます)
   - 「グループ・複数人トークへの参加を許可する」を**オン**
   - **応答メッセージ・あいさつメッセージをオフ**(自動返信をしないため)
3. LINE Developers のチャネルで、次の設定をします。
   - **チャネルシークレット**を `config.php` に入れます(ほかには書かないでください)。
   - **Webhook URL** に `https://line-hook.kamisei.co.jp/` を入れて、「**検証**」を押します。成功と出ればOKです。
   - 「**Webhookの利用**」を**オン**にします。
   - 「**Webhookの再送**」が使える場合は**オン**にします。書き込みに失敗したときに、LINEがもう一度送ってくれます。
   - **チャネルアクセストークンは使いません。**(この仕組みは返信をしないため。発行した場合も、どこにも書かないでください)

### 4. テストグループの準備とグループIDの確認
1. **テスト専用のLINEグループ**を、テストの参加者だけで新しく作ります。
2. `config.php` の `log_join_group_id` を `true` にします。
3. グループに、公式アカウントを招待します。ログ(`log_file`)に、`joined_group group_id=C…` と出ます。
4. そのIDを `allowed_group_ids` に入れ、`log_join_group_id` は **`false` に戻します**。
5. グループで、架空の内容を投稿して確かめます。
   - 「【対応】架空の確認です」→ シートに1行入る
   - 「架空の雑談です」→ 入らない
   - 画像 → 入らない

### 運用メモ
- `data/events/` には、イベントIDごとに小さなファイルができます。数が増えすぎたら、古いもの(1か月以上前など)を消しても構いません。
- ログは、処理の結果だけです。大きくなったら消して構いません。
- Dot には、このシートを**読み取り専用**で共有する想定です(別の作業で設定します)。
